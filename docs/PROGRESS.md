## Module 5 - Rating
Done: Elo for players AND problems. E = 1/(1+10^((Rp-R)/400)), R' = R + K*(S-E); K = 40 for attempts 1-10, 24 for 11-30, 16 after (the 30 boundary is my assumption); problem K = 8 (mirror game vs the player's overall rating); floor 800. Per-tag ratings (own attempt counter and K per tag; every tag of the problem is updated) and rating_history (one row per rated submission and scope 'global' / 'tag:<slug>', with raw/effective score, E, K, old/new).
Rules I chose (not in the brief): a submission is rated only if it is the user's first on that problem or beats their previous best raw score (so re-submits cannot farm or drain rating; a solved problem is never rated again). Hints: POST /problems/{id}/hints/{level} records the opened level; the deepest level opened BEFORE the rated submission multiplies S by 0.9 / 0.75 / 0.5 (levels 1/2/3). The checker result (score, solved) is never changed by hints. Admins are rated like everybody else. Problem.rating (int, shown) is the rounded value of an exact float kept in problem_ratings; if an admin edits the rating, the exact value restarts from it.
API: GET /rating/me (rating, attempts, per-tag), GET /rating/me/history?tag= (oldest first, for the chart), GET /problems/{id}/hints (hints I opened), POST /problems/{id}/hints/{level}.

## Module 8 (stage 2) - Duel
Done (backend only): 1v1 duels without Redis.
- Matchmaking: in-memory waiting list (duel/waiting.py), matched by duel rating within +-100, the window widening by 50 every 15 s (the NARROWER of the two players' windows decides; longest waiter is served first, closest rating). Lost on restart: players re-join.
- Match = 3 problems neither player has solved (checker.solved_problem_ids = solved=true), chosen at random among the 9 closest to the pair's average rating, ordered easiest first. If fewer than 3 are available the pair keeps waiting. Server-side 60 min deadline.
- Rules live in a pure state machine (duel/state.py, injected clock): first to solve all wins; at the deadline: more solved, then higher total score (sum of best score per problem), then lower penalty (minutes to the LAST solve + 5 per failed submission), else a DRAW; 60 s reconnect grace then automatic loss (both gone: the one who left first loses). Submissions to an already solved problem and submissions made after the deadline are ignored. Failed = a checked submission with solved=false on a problem not yet solved (failures on problems that stay unsolved count too - my literal reading of "5 min per failed submission").
- Timers are server-side only: one supervisor task ticks every second (matchmaking, deadline, grace); nothing a client sends can start/extend/end a match. The deadline waits (max 120 s) for submissions still being checked that were made before it.
- Duel Elo (duel/elo.py): K=32, win 1 / draw 0.5 / loss 0, floor 800, separate from the training rating (table duel_ratings with games/wins/losses/draws). Finished matches persisted in SQLite (duel_matches, duel_participants incl. rating before/after, duel_match_problems, duel_player_problems).
- API: POST/DELETE /duel/queue, GET /duel/me, GET /duel/rating, GET /duel/matches (history), GET /duel/matches/{id} (live, participants only), POST /duel/matches/{id}/submit (then poll GET /submissions/{id}), GET /duel/matches/{id}/result (post-match page: per player solved, total score, penalty, failed submissions, rating change, and per problem: solved, best score, failed, solve minutes, penalty; participants + admins, finished only).
- WebSocket /duel/ws: first frame {"type":"auth","token":...}; the server pushes state (idle / waiting / active); about the opponent it sends ONLY solved count, total and a connected flag - never code, scores or submissions; code only travels over REST. An open socket = presence; closing the last one starts the 60 s grace; reconnecting inside it cancels it; several tabs are fine. Blocked users get close code 4403, bad auth 4401.
- Decision (the user answered "1" without answering my open question, so I used my stated default): duel submissions do NOT change training ratings (no player/problem Elo update) but DO count as solved=true for the archive status, solved counts and tag unlocking.
Checker changes: Submission.duel_match_id, add_listener()/CheckedSubmission (the duel module registers a listener; no import cycle), pending_duel_count. problems.service: problem_ratings(), titles_for().

## Fix - C++ checker verified with a real g++ (w64devkit, GCC 16.2.0)
The C++ path had never been run before (no g++); the first real run found two bugs, both fixed in checker/runner.py:
- `-static` was inserted between `-o` and the file name (`insert(-2, ...)`), so g++ wrote a file called `-static` and no prog.exe existed: EVERY C++ submission scored 0. Now inserted before `-o`.
- On Windows a crashed or killed program keeps its .exe locked for a moment, and deleting the temp dir raised PermissionError out of check() (it could turn a correct answer into 0). The temp dir is now removed by `_remove_workdir` with retries and never raises.
Result: the 5 C++ tests that were skipped now run and pass (compile error, infinite loop, memory hog, crash, correct solution). Full suite: see the last run in the chat; no skips left.
